# 로드맵 / 시리즈 계획

## "코딩 도감" 시리즈 개념

포켓몬 도감처럼, 매 시리즈(`#번호`)는 하나의 기술 **챕터**를 다룹니다. 챕터 안의 각 주차는 `NO.001`, `NO.002`처럼 서로 다른 개체를 관찰하고, 매주 글의 마지막에 그 개체를 "코딩 도감"에 정식 등록합니다. 마지막 주차에서는 해당 주차 개체 등록과 함께 챕터 전체의 완성을 표시합니다.

> **주차 수는 개체 수를 따릅니다.** 한 주에 개체 하나를 등록하므로, 개체가 5마리인 챕터는 5주입니다. 자세한 기준은 [다음 챕터 선정 기준](#다음-챕터-선정-기준)을 참고하세요.

챕터 순서는 사용자의 게임 [codigdex](https://github.com/codingnanyong/codigdex)의 도감 번호를 따릅니다(2026-11-02 결정). 이전 계획은 `#03` Docker부터 Data Engineer 실무 챕터를 앞당기는 순서였지만, 이제 `#01` Git → `#02` Linux → `#03` HTML/CSS → `#04` JavaScript로 게임 순서대로 이어집니다. Docker는 `#11`, 데이터 파이프라인은 `#18`입니다. 사용자의 직무는 Data Engineer이며, 실무 경험은 해당 챕터에 도달했을 때 소재로 씁니다.

### 실무 경험 소재

사용자는 실제 업무에서 Airflow·Kafka·dbt를 사용하고, PostgreSQL + TimescaleDB 기반 Medallion Architecture를 구현했으며, 인프라를 Docker 기반에서 Kubernetes 기반으로 전환한 경험이 있습니다. 순서는 게임을 따르되, 해당 챕터에 도달하면 이 경험을 소재로 씁니다. Medallion Architecture처럼 게임에 대응 개체가 없는 주제는 도감 번호가 없으므로 정규 챕터 밖의 글로 다룰지 그때 정합니다. 데이터 모델링, CDC, 파티셔닝, 쿼리 최적화, 백필 전략 같은 후보 주제도 같은 기준으로 관련 챕터에 녹이거나 별도 글로 다룹니다.
